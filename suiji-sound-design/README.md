对应需求表：[`岁记-交互音效需求表-v1.0.md`](岁记-交互音效需求表-v1.0.md)

```

│  ├─ wav/                       29 条 44.1kHz/16bit 单声道 WAV（母版）
```

双击 `preview/index.html` 即可试听（走相对路径加载 `ogg/`，无需起服务器）。页面按 S/T/E 分组，每张卡标注 ID、标题、触发场景、时长、相对响度档、峰值与高频占比；顶部可调试听音量并一键切到「夜间 20%」。

## 重新生成

```bash
cd synth
python synthesize.py          # 合成 29 条 WAV + 写 manifest.json（约 60s）
python audit.py               # 机检 -> ../review/audit.md
python to_ogg.py              # 转 Ogg Vorbis -> ogg/（需要 python-soundfile 或 ffmpeg）
python render_spectrograms.py # 频谱图 -> ../review/spectrograms.png

cd ..
python preview/build_preview.py  # 预览页 -> preview/index.html
```

预览页在 `synthesize.py` 之后运行即可；它优先引用 `ogg/`，缺 OGG 时回退 `wav/`，两者都缺的条目会跳过并告警。

依赖：Python 3.10+、numpy、Pillow；转码用 `pip install soundfile`（装不上则回退 ffmpeg）。
合成用固定随机种子，同一条素材重跑字节一致，便于 diff 与版本追溯。

## 处理链与两个关键设计

**定型（`shape`）**：100 Hz 高通 → 3.5 kHz 以上 -12 dB 搁架 → -60 dBFS 裁尾 → 淡入 4 ms / 淡出 45–120 ms。
淡出长度随结尾电平自适应：卡林巴的自然衰减在时长预算点上常还有 -15~-30 dB，45 ms 直落会听出"被剪断"。

**定标（两遍求解）**：需求表原稿把「-3 dBFS 峰值」与「-20 LUFS 成就音」并列为硬指标，实测二者对 1–3 秒的短音效互相矛盾（详见需求表 §2.1.1）。做法是：

1. 先量每条素材定型后的峰均比（PLR，实测 11–17 dB）；
2. 取 `ref = min(CEIL / (PLR_i × 10^(rel_i/20)))` 作为全表统一基准；
3. 每条按 `ref × 10^(rel_i/20)` 缩放。

结果是响度阶梯**逐条精确成立**、峰值**全部不越线**、**全程没有任何限幅器**——代价是绝对响度比原目标低 1–4 LU，因此验收改为相对阶梯（A-09）。若产品坚持绝对 -20 LUFS，只能放宽峰值或接受限幅削平拨弦瞬态，已登记为 B-06。

**高频预算（`check_hf`）**：单级 -12 dB 搁架后最高的 S-11 也只有 1.07%，8% 预算从未吃紧，因此不做"超标就逐档加深低通"的自动救场——那只会把音色默默削闷。真超标会直接抛错，要求回编曲层改泛音。

## 接进 App

SoundPool 加载 `ogg/`，通道按需求表 §2.2：

- S 组 → `USAGE_ASSISTANCE_SONIFICATION`（跟随系统"触摸提示音"开关）
- T / E 组 → `USAGE_NOTIFICATION` + `CONTENT_TYPE_SONIFICATION`（可被勿扰接管）

三条实现红线（需求表 §八）：

1. **S-03 必须等服务端确认再播**（NFR-06 / FR-39），不能在乐观更新时就响；
2. 音效开关与振动开关**分开**，且夜间静默时段（默认 22:00–07:00）优先于一切（B-01）；
3. 体温 ≥38℃、百分位 < P3 等场景**不得出现任何警示音**（A-05 / RK-01），那里只有静态文案。
