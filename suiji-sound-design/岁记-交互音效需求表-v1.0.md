## 一、设计目标与世界观

岁记的核心场景是**深夜、单手、宝宝就在旁边**。音效的第一目标不是"好听"，而是"确认到达了、且没有吵到任何人"。

| 项 | 约定 |
| --- | --- |
| 听觉关键词 | 温润、贴近木质/指腹、夜间感、非电子、非医疗仪器 |
| 推荐音色 | 卡林巴（拇指琴）、软木琴、指触弦、气声包络的合成音；避免钢琴高音区、铃声、合成器 lead |
| 绝对禁止 | 系统蜂鸣（beep）、警报音、金币/得分音、电商促销音、任何带"惩罚感"的音色 |
| 情绪预算 | 全 App 只允许**里程碑达成**一处使用庆祝音（E-01），其余全部保持中性偏正 |
| 一句话判据 | "这条声音在 23:40、婴儿床边、音量 20% 播放时，会不会让大人惊醒或烦躁？"会 → 不合格 |

### 2.1 声学参数

#### 2.1.1 峰值与响度不能同时取满（v1.0 补订）

原表把 "-3 dBFS 峰值" 与 "-20 LUFS 成就音" 并列为两条硬指标，实测发现二者对 1–3 秒的短音效**互相矛盾**：

- 本表音色主体是卡林巴拨弦 + 木质敲击，峰均比(PLR)实测 8–17 dB；
- 若成品要达到 -20 LUFS，在 -3 dBFS 峰值上限下只允许 PLR ≤ 13 LU；
- 快门音(S-06, PLR 16.8 dB)、开关音(S-11, 17.2 dB)、日记归档(E-06, 17.0 dB)必然越线。

用限幅器硬压会把这几条压成"没有动态的方块"，拨弦的起振与余韵被削平；逐条降响度则会把整表阶梯拉偏。

**处理原则（相对阶梯优先）**：

1. 先定型（滤波、裁尾、淡变），此时高频占比与音色已经收敛，不再改动；
2. 用 PLR 最高、目标最响的那条素材反推一个**全表统一基准** `ref`，其余素材按各自阶梯相对值缩放；
3. 结果是：阶梯**逐条精确成立**（偏差 <0.05 dB），峰值**全部 ≤ -3 dBFS，全程无限幅器**，代价是绝对响度整体比 -20/-24 LUFS 低约 1–4 LU。

按此原则量产的实测基准：S-03 = -20.7 LUFS，成就音 ≈ -21.7 LUFS，交互音 ≈ -26.7 LUFS。

**验收口径**：绝对 LUFS 改为**单向告警**——高于目标值必须改，低于目标值 4 LU 以内不算失败；判定响度是否合格以新增的 A-09（相对阶梯）为准。若产品坚持绝对 -20 LUFS，唯一自洽的解法是放宽峰值上限到 -0.3 dBFS 或接受限幅，需另开决策项（登记为 B-06）。

「音量档」定性列到量产数值的映射（`synth/manifest.json` 的 `target_rel_db` 即按此取值）：

| 音量档 | 相对 S-03 目标 |
| --- | --- |
| 极低 | -9 ~ -10 dB |
| 低 | -3 ~ -7 dB |
| 中低 | -1 ~ -2 dB |
| 中 | 0 dB（基准档，仅 S-03/S-06） |

同档内的具体 dB 不是随意取的，用来编码可辨识次序（如 S-01 展开 -6 比 S-02 选中 -7 略轻，构成"轻→更轻"的两拍；S-08 危险确认 -0.5 与 S-03 同档但略低，靠音色而非音量区分严重程度）。逐条取值以 `synth/manifest.json` 的 `target_rel_db` 为准。

阶梯按 **K 加权 RMS** 而非峰值排布，所以"S-03 中低、S-06 中"这两档在 RMS 上同为 0 dB 是自洽的：快门是宽带瞬态，峰均比 15.7 dB，比两音动机 S-03 的 14.4 dB 高 1.3 dB，且能量集中在前 30 ms，同等 RMS 下主观更"响、更突出"。若改用峰值对齐，快门会被压成闷响。

响度基准 S-03 取 0 dB 是因为它是全 App 触发频次最高的音效（每条记录一次），其余条目围绕它安排可辨识度。

#### 2.1.2 时长口径（v1.0 补订）

原表的时长是按"点击即走"的电子音写的（如 S-01 70–90 ms），与本表自己指定的卡林巴音色**物理上不兼容**：拨弦音要衰减到不可闻（-60 dB）需要 6.9 倍时间常数，而卡林巴舒服的时间常数在 0.16–0.30 s 之间，对应 1.1–2.1 s 的自然余韵。把 90 ms 做满只剩"咔嗒"，音色世界观就不成立了。

因此时长列已按**实际交付值**重写，口径为：

- **起点**为起振首样本，**终点**为包络最后一个高于 -60 dBFS 的样本（与 §2.1「收尾」同一把尺子）；
- 若素材在预算点上仍有 -15~-30 dB 的能量，用 120 ms 淡出收尾（§2.1 只要求 ≥30 ms），避免听出"被剪断"；
- E 组（成就音）保留完整余韵，S 组（交互音）用 0.16 s 衰减常数收得干脆，二者时长差是设计意图而非失控。

结论：**S 组 100–590 ms、T 组 370–790 ms、E 组 260–1620 ms**。这三段区间才是本音色体系可交付的真实约束，评审若要求恢复到原表的两位数毫秒，等同要求更换音色（见 §一 设计目标与世界观），需重新立项。

### 2.2 播放通道（客户端实现约束）

| 类型 | Android Stream / Usage | 理由 |
| --- | --- | --- |
| 交互音（S 组） | `AudioAttributes.USAGE_ASSISTANCE_SONIFICATION` | 走系统"触摸提示音"开关，用户关系统触摸音时自动静音 |
| 计时/成就音（T/E 组） | `USAGE_NOTIFICATION` + `CONTENT_TYPE_SONIFICATION` | 需可被系统勿扰（DND）接管，这是夜间不打扰的兜底 |
| 长流程完成（E-04/E-08/E-09） | 优先系统通知渠道，App 前台才播音频 | 用户此时通常已离开页面 |

**必须遵循的开关优先级（从高到低）**：
1. 系统静音/振动模式 → 全部静音
2. 系统勿扰（DND）命中时段 → 仅振动
3. 应用内「夜间静默时段」（默认 22:00–07:00，可关） → 仅振动
4. 应用内「音效」分档（音效+振动 / 仅振动 / 全静默）
5. TalkBack / 无障碍模式开启 → 全部静音（NFR-13：音效不得作为唯一信息通道）

## 七、验收标准

| 编号 | 检查项 | 判定 |
| --- | --- | --- |
| A-01 | 静音路径完整性 | 依次开启「系统静音」「DND」「应用内仅振动」「TalkBack」四态，**每条音效均须有可感知的等价反馈或明确静默**，无一处依赖听觉传达唯一信息（NFR-13） |
| A-02 | 夜间压力测试 | 在 23:40、媒体音量 20%、手机距人耳 1 m 场景实测：完成 T-04 + S-03 + E-01 全链路，主观评分"不惊醒婴儿"≥ 4/5，由 ≥3 名评审者打分 |
| A-03 | 时序穿帮检查 | 断网、弱网（RTT 800 ms）、服务端 500 三种注入下，S-03 **绝不误播**（NFR-06 / FR-39）；S-01 延迟 ≤50 ms（FR-01 的 300 ms 面板预算内） |
| A-04 | 情绪预算合规 | 全局扫描：除 E-01/E-07/E-10 外，任何音效不得含上行琶音、铃铛、和声渐强等庆祝语汇 |
| A-05 | 医疗红线 | 体温 ≥38℃、百分位低于 P3、晚于参考范围三场景（FR-16 / FR-08 / FR-12）**不得出现任何警示音、警报音或急促振动**（RK-01） |
| A-06 | 频段与刺耳度 | 3.5 kHz 以上能量占比 ≤8%；在低端机单扬声器（RK-11 机型矩阵）复测，主观刺耳度 ≤2/5 |
| A-07 | 无骚扰性 | 连续 20 次记录操作中，音效不得出现叠音、重复触发或必须手动关闭的情况（FR-40 精神延伸） |
| A-08 | 时长预算 | E 组全部 ≤2000 ms 且不阻塞跳转，G-01 的 P95 ≤15 s 记录耗时在开启音效后无回归 |
| A-09 | 响度阶梯 | 每条成品与 S-03 的 K 加权 RMS 差值落在 §2.1.1 `target_rel_db` 的 ±1 dB 内；同时峰值 ≤-3 dBFS。绝对 LUFS 按 §2.1.1 单向告警处理，不作为失败项 |
