AI 成长日记重设计

产品：岁记 App（家庭成长记录）  ·   版本：v1.1（新增独立 AI 服务拆分）  ·   日期：2026-11-18  ·   上游文档：PRD v1.0  ·   状态：待评审

00技术结论与依赖评估

结论：本设计不引入任何新技术栈，但按产品决策新增一个独立后端服务 ai-server（FastAPI + httpx，与主服务同栈，零新增框架/中间件）。部署形态：49.233.77.155 同机 docker-compose 新增 ai 容器，不暴露公网，主服务内网转发——客户端访问链路不变（nginx 唯一公网入口）。

可能引入新技术的点评估结论
独立 AI 服务（ai-server）
用户决策 2026-11-18		新增服务、不新增技术。新目录 suiji-server/ai/（同仓库子目录，部署脚本无需改动），FastAPI 应用 + 独立 Dockerfile + compose 服务项；职责 = LLM 编排 + 输出守卫 + 句库兜底，见 §0.1。
定时任务框架（APScheduler / Celery / Cron）
FR-06 自动生成 · FR-07 月报		不引入。PRD 的触发语义是「周一/月初 任一成员首次打开 App」，天然是客户端触发型——客户端首启上报 → 服务端幂等判断并生成。无需常驻调度器。现有后台 asyncio 循环（cleanup 每 6h）如需兜底可零成本加一步，不作为依赖项。
向量检索 / Embedding（照片语义匹配选图）
FR-04 图文混排		不引入。照片候选量级为单周 ≤ 几十条，直接把照片事件的元信息（条目日期、条数、同一记录的心情文字）放进 prompt 让模型选 entry_id，无需向量库。
对象存储 / 转码等媒体能力
FR-04		不新增。嵌图只存引用（entry_id + photos 数组下标），缩略图/预览走现有 media 缓存与 sj-media-preview，媒体字节不经日记表。
LLM 能力升级（结构化输出/更大模型）不更换。继续 DashScope qwen3.5-flash + enable_thinking:false，标题/摘要/选图通过 prompt 输出 JSON 扩展字段实现；现有 60s 超时与重试参数保留。LLM API Key 从主服务 env 迁移到 ai-server env，主服务不再持有 Key。
并发去重（分布式锁）
FR-06		复用现有 Redis（redis_client 已在依赖中，锁归主服务）做家庭级短锁，叠加数据库查询兜底，见 §6。

0.1 独立 AI 服务架构（ai-server）

服务拓扑

客户端 App（uni-app） ↓ HTTPS（唯一公网入口，链路不变） nginx :30080 → suiji-server（主服务） ↓ 内网 HTTP（compose 网络内，不暴露公网） ai-server（新容器，仅内网可达） ↓ HTTPS 外呼 DashScope（qwen3.5-flash）

ai-server 无数据库连接、无 Redis、无鉴权中间件——它只被主服务调用（compose 内网），攻击面为零公网暴露。

职责边界（拆分原则：ai-server 无状态纯计算）

职责归属理由
素材收集 _collect / 门槛判定 / BABY_PROFILE 隐私白名单主服务需要读 DB；隐私过滤在数据源头完成，出域素材经内网传给 ai-server
API 路由 / 鉴权 / 权限 / 落库 / 幂等锁 / 通知 / 草稿清理主服务业务状态全部在主服务，ai-server 不碰存储
快问出题（GET /journals/questions）主服务纯规则 + 读素材，不调 LLM，无拆分价值
LLM 调用 + 重试循环 / 守卫（禁词·白名单·引用·句式）/ prompt v2 / 句库兜底ai-server守卫必须与 LLM 重试同进程闭环；LLM Key 只在这里
段内选图解析（entryId→photos 下标）ai-server（结果）
校验归 主服务		解析在生成循环内完成；落库前主服务再校验 entryId 归属
纵深防御终检（收到 ai-server 结果后复扫禁词）主服务内网响应也复跑轻量禁词扫描，守卫逻辑不单点信任

ai-server 接口契约（内部，仅主服务调用）

# POST /generate（内网，无鉴权；素材由主服务收集并过滤后传入）
{ "kind": "week",                       /* week|month */
  "rng": {"start": "2026-11-09", "end": "2026-11-15"},
  "baby": {"name": "朵朵", "age_months": 7, "gender": "girl"},  /* 已过隐私白名单 */
  "facts": ["…主服务 _collect 产物（§4.2 结构）…"],
  "answers": [{"q": "…", "a": "…"}] }

# 响应（主服务直接落库的字段）
{ "title": "会翻身了的一周", "summary": "…",
  "paras": [{"text", "src", "entryIds", "media":[{"entryId", "idx"}]}],
  "model_version": "qwen3.5-flash", "prompt_version": "v2",
  "fallback": false }              /* true = ai-server 内部已走句库兜底 */

# GET /healthz → {"ok":true}（compose healthcheck 用）

失败降级链（三层）

  • 层 1（ai-server 内）：LLM 失败/守卫拦截 → 重试 → 句库兜底，响应 fallback:true，主服务照常落库。
  • 层 2（主服务内）：ai-server 超时/不可达（内网 httpx 90s 超时）→ 主服务调用本地保留的现有 template_diary 作为服务级兜底，model_version="template"——自动生成场景静默成功，手动生成照常出结果。
  • 层 3：两者都不可用（如零素材）→ 维持现有空态模板，不发通知。

代价：句库模板逻辑在 ai-server（主）与主服务本地 template_diary（降级）各存一份。接受此重复以换可用性；本地版本可保持现状简版，不追求两侧一致。

部署形态（compose 变更）

  • 代码位置：suiji-server/ai/（app.py + guard.py + prompt.py + 兜底句库 + Dockerfile），随 --local-dir suiji-server 部署流程同步，deploy 脚本零改动。
  • compose 新增 service：ai，仅内网端口（如 8100，不映射 host 端口），healthcheck 轮询 /healthz，restart unless-stopped。
  • 主服务新增配置项 AI_SERVICE_URL=http://ai:8100（env），未配置或探测失败 → 自动走层 2 本地兜底（灰度安全：先部署不配置，逐步切换）。
  • env 变更：LLM_API_KEY/LLM_MODEL/LLM_API_BASE 迁移至 ai 服务环境；主服务移除后需保留兼容读取一个版本（读到也只用于层 2 判断 llm_configured，逐步下线）。

2.2 复用不改的模型

  • Baby：name（小名）、birth_date（月龄由此计算）、gender 已存在，BABY_PROFILE 直接拼装，无迁移。隐私规则：仅这三个字段出域，姓氏/家长姓名继续不出域。
  • Entry：mood/note/voice 类型与 payload 已存在（voice 转写文本在 payload.voice 内）；MOOD 素材直接从既有 entries 过滤提取，无迁移。
  • Setting：「自动生成成长日记」开关落在现有 setting 表的 family/ai 配置区（settings 接口已支持自由键值），前端设置页加一个开关项；默认开启（读不到即视为开启）。
  • Notification：自动生成通知复用现有 notify_family 通道，无表变更。

03API 设计

前缀 /api/v1/journals，鉴权沿用现有 get_auth / require_write；「创建者任意、成员仅改本人草稿」的 _assert_writable 规则不变。对外接口全部由主服务提供（客户端无感知拆分）；generate/auto 内部经 AI_SERVICE_URL 委托 ai-server，失败降级见 §0.1。

端点变更
GET /journals
现状接口		 出参增加 title / summary / qa / kind / source（rows.journal_row 扩展）；paras[].media 原样下发。旧客户端不识别新字段自然忽略，向前兼容。
POST /journals/generate
FR-01/02/03/04		 入参扩展（JournalGenerateIn）：
answers: [{q: str, a: str}] = [] — 快问回答（单题 ≤200 字，空答案过滤）；
regenerate: bool = false — 快问补答触发的重新生成：为 true 时必须命中同 family+baby+range 的既有草稿，覆盖其正文/标题/摘要/嵌图，保留 qa 并合并新回答，归档态返回 422「归档后不可重新生成」；
kind: "week"|"month" = "week" — 月报手动入口预留（PRD Q1 待定，接口先行支持，前端本期不暴露入口）。
PUT /journals/{id}
FR-02/04/05		 JournalUpdateIn 增加 title / summary（草稿态可改，长度校验 12/40 字上限截断）；paras 内的 media 引用随段落保存，服务端校验 entryId 属于本家庭且未被软删（防越权/防悬空）。
GET /journals/questions
新增
FR-03		 快问出题。query：kind（缺省 week）、range_start/range_end（缺省近 7 天）。服务端跑 _collect 轻量收集，按 PRD 优先级出题（里程碑→照片≥5→心情→兜底），返回 {questions: [{id, text, hint}]}，最多 2 题。只读权限（get_auth）。
POST /journals/auto
新增
FR-06 · FR-07		 自动生成检查（客户端首启调用一次）。入参：{trigger: "week_open"|"month_open"}，客户端不传日期——服务端按 UTC 判断今天是否周一/每月 1 日（避免客户端时钟不可信）。响应：{generated: bool, journal: row|null, skipped: "not_due"|"dedup"|"insufficient"|"disabled"|"quiet_hours"|"regenerating"}。详见 §6 幂等方案。require_write 权限（只读成员不触发）。

04生成管线重构 FR-01 · FR-02 · 核心

4.1 管线流程（重构后；节点标注执行位置）

主服务负责素材与落库，ai-server 负责 LLM 编排与守卫（边界见 §0.1）。主服务在①后调用 POST ai/generate（内网 90s 超时），把②③④整体委托给 ai-server。

① _collect 素材收集（扩展）【主服务】新增：BABY_PROFILE（name/birth_date→月龄/gender）；MOOD（本周 mood/note/voice 文本，单条截断 200 字，按「含“第一次”/“最”/被标星」优先选 ≤5 条）；QUICK_ANSWERS（入参 answers 注入）。降权：CARE_STAT 压缩为单条汇总字段 digest，不再产出分项排比素材。保留：MILESTONE（“第一次”系标记 first=true）、MEASUREMENT、MEDIA（补 photo 条目的 mood 附文，供选图）、ROUTINE。
↓ 素材不足门槛判定（FR-06）【主服务】：总条数 ≥3 或含里程碑/照片/心情 → 继续；否则 auto 返回 insufficient，手动返回现有空态模板
② POST ai/generate → _call_llm（prompt v2）【ai-server】system prompt 重写：家人手记口吻、3–6 段结构（开篇画面感→1–2 个瞬间→收束）、每段 40–120 字；输出 JSON 扩展为 {"title","summary","paras":[{"text","src","media":[entryId]}]}——模型只回 entryId，ai-server 把 photos 下标解析进 media 并限制每段 ≤2、全文 ≤6。CARE_STAT.digest 作为可选收尾素材，prompt 明示禁止排比。失败重试 1 次（现有逻辑）。
↓ 失败重试 1 次
③ OutputGuard 守卫（扩展）【ai-server guard.py】保留：禁词表（含 title/summary 一并扫描）、引用完整性、数字白名单——白名单比对 bag 扩大：facts + mood/voice 原文 + qa 回答序列化文本。新增 check_report_style 句式守卫（§4.3）。任一拦截 → 重试 1 次 → 句库兜底。
↓ 两次失败
④ 句库兜底 v2【ai-server fallback.py】按素材类型（里程碑/心情/照片/统计）预置 3–5 套叙事句式随机轮换，数字只出现在状语位；同时产出兜底 title（「{里程碑名}的一周」类）与 summary。兜底文案不嵌图。响应标 fallback:true。ai-server 整体不可达时主服务层 2 兜底（§0.1 降级链，本地保留现状 template_diary 简版）。
↓ ai-server 响应回主服务（层 2 兜底失效时由本地 template_diary 生成）
④' 纵深防御终检【主服务】对 ai-server 返回的 title/summary/paras 复扫禁词（轻量本地实现），命中则丢弃 LLM 结果转层 2 兜底；再校验 media 引用的 entryId 属于本家庭且未软删，越权/悬空引用直接剔除。
↓
⑤ 落库 + 通知【主服务】regenerate=true → 原地覆盖既有草稿（保留 qa 合并 answers，updated_at 刷新）；否则新建行。prompt_version="v2"；通知文案按 source 分流（§6.4）。notify_family 复用。

4.2 素材结构（facts 输出新增项）

{"type": "BABY_PROFILE",   "name": "朵朵", "age_months": 7, "gender": "girl"}
{"type": "MOOD", "items": [{"date": "11-12", "text": "今天第一次自己扶站…", "entry_id": "e_1", "star": true}]}  /* ≤5 条 */
{"type": "QUICK_ANSWERS", "items": [{"q": "…", "a": "…"}]}
{"type": "CARE_STAT", "digest": "本周共记录 23 条，喂养与睡眠节奏平稳"}  /* 单串，非分项对象 */
{"type": "MEDIA", "photos": [{"entry_id": "e_9", "date": "11-12", "count": 3, "caption": "配文：笑得好开心"}]}  /* 供模型选图 */

隐私白名单落地点：主服务 _collect（唯一决定什么素材进入内网请求）+ ai-server prompt（对传入素材只组装不新增）。BABY_PROFILE 仅取 Baby.name（小名）三个字段；家长姓名、联系方式、照片原图字节、诊断类 payload 一律不进素材层，ai-server 收到的已是过滤后的白名单素材。

4.3 句式守卫 check_report_style

# ai-server guard.py 新增（自 output_guard.py 移植）；「X 次/段/张/条/回/顿」计数短语连续出现 ≥2 组 → 报表式违规
PATTERN = re.compile(r"\d+\s*(次|段|张|条|回|顿|个)(?=\s*[、，。]|$)")
def check_report_style(paras) -> bool:  # True = 合规
    for p in paras:
        if len(PATTERN.findall(p["text"])) >= 2:
            return False
    return True
  • 正则按「数字+量词后紧跟标点/结尾」限定，避免误杀「150ml」「6 小时」「P48」类数值（不带上述量词）。
  • 对 title/summary 单独跑：summary 禁止出现任何统计数字（PRD FR-02），title/summary 同跑禁词表。
  • 里程碑固有名称不误杀的现状由禁词表收窄逻辑保证，本设计不再触碰 BANNED 表。

05快问出题与段内选图 FR-03 · FR-04

5.1 出题决策（GET /journals/questions 内实现）

素材条件题目
本周有里程碑「{里程碑名}新技能，当时发生了什么小故事？」（取最近一条）
照片 ≥5 张「这周哪张照片背后有故事？」
有 mood/voice 记录「这周 TA 情绪最特别的一次是什么时候？」
兜底「这周最让你印象深刻的瞬间是什么？」

按优先级取前 2 题；纯服务端计算（读 entries/milestones），不调 LLM，毫秒级返回。question 对象带 id（client 透传回 generate 即可，q 文本随 answers 回传落库）。

5.2 段内选图（LLM 选中 → 服务端解析落库）

  • MEDIA 素材为模型提供 entry_id + date + caption；模型输出 media:[entryId]（每段 ≤2）。
  • 服务端把 entryId 解析为该记录 payload.photos 下标（取前 2 张），超全文 6 张的按段落顺序截断；视频条目不进 media。
  • 客户端渲染：按 media 引用从现有 media 缓存（diaryMedia 同源）取缩略图，点击进 sj-media-preview 全屏预览；未被引用的照片/视频落「更多照片」横向条（现状 dc-media 逻辑降级为此）。
  • 编辑页增删嵌图：前端从本日记周期媒体池中选取/移除，PUT 时随 paras 保存，服务端校验 entryId 归属（§3）。
  • 模板兜底产出的 paras 一律无 media（兜底无语义匹配能力），全部照片落「更多照片」。

06自动生成与幂等方案 FR-06 · FR-07

6.1 总体链路

客户端 App 首启（index onShow）──POST /journals/auto──▶ 服务端 5 道闸门──全通过──▶ 生成 + 通知全部成员

客户端本地不做周一/月初判断、不读开关，只管首启上报一次（带本地去抖：同一自然日只请求一次，写本地存储）；全部判断收敛在服务端，单一事实源。

6.2 服务端五道闸门（POST /journals/auto）

  1. 日期闸：服务端 UTC 今天是周一（trigger=week_open）或每月 1 日（trigger=month_open），否则 skipped:"not_due"。
  2. 开关闸：读家庭设置「自动生成成长日记」（默认开启），关闭则 skipped:"disabled"。
  3. 去重闸：同 family + baby + 上周一~上周日（自然周，服务端计算）已存在草稿或归档日记 → skipped:"dedup"。月报同理按自然月。
  4. 并发闸：redis SETNX sj:auto:{family_id}:{trigger}:{date_key} TTL 90s（≥ LLM 最长耗时 60s×2）；抢锁失败 → skipped:"regenerating"（另一成员正在生成）。锁超时兜底 + 数据库复查去重，双保险。
  5. 素材闸：门槛判定（§4.1），不足 → skipped:"insufficient"，不生成、不通知。

失败静默（FR-06）：管线全失败且兜底不可用时，auto 返回 {generated:false, skipped:"failed"}，不抛 5xx、不发通知；客户端不重试（次日首启天然重试）。手动 generate 不受影响。

6.3 为什么不需要调度器

PRD 触发语义是「当天任一成员首开」——凡是没有成员打开 App 的日子，生成与通知也无意义（通知无人看）。客户端触发 + 服务端幂等的组合：语义等价、零新增进程、错误面更小（无调度器单点）。若未来要求「无人打开也要生成」，再评估 APScheduler，本期不做。

6.4 通知分流

  • source="auto"：notify_family 全员推送「本周成长日记已生成，看看这周的小故事吧」，不做本人过滤（现有 notify_family 的 actor 过滤按 source 跳过）；月报文案对应替换。
  • source="manual"：维持现状文案与本人过滤逻辑不变。
  • 通知走现有 Notification 表与 /events/count 角标轮询，无通道变更。

09测试要点

  • 守卫单测：句式守卫正反例（「喂养 18 次、睡眠 12 段」违规；「平均每顿 150ml」放行；「6 小时」放行）；数字白名单对 mood/qa 原文数字放行；title/summary 禁词扫描。
  • 管线集成：LLM 输出含 media 越界（每段 >2 / 全文 >6）截断；模型回错误 entryId → 丢弃该引用不报错；regenerate 对归档态 422；qa 合并保留。
  • 服务拆分：ai-server 不可达 → 主服务层 2 兜底出模板文案且不 5xx；ai-server /healthz 通过；主服务终检复扫命中禁词 → 丢弃 LLM 结果走兜底；AI_SERVICE_URL 未配置 → 全量走本地兜底（灰度路径）。
  • 幂等：同家庭双成员并发 POST /journals/auto → 仅一次生成（Redis 锁 + 去重复查）；非周一返回 not_due；开关关闭 disabled；素材不足 insufficient 且无通知。
  • 权限：只读成员调 auto/questions/generate 被拒；成员改他人草稿 403 现状回归；media entryId 越权（别家家庭）被服务端过滤。
  • 迁移：alembic upgrade head 在含旧数据的库上执行，旧日记行读取正常、列表回退显示；downgrade 可回滚。
  • 前端：旧数据无标题卡渲染；快问面板跳过/填写/超 200 字截断；嵌图增删后归档不可改；月报标识。
