# 微信 / 支付宝登录三端（H5、微信小程序、App）接入调研报告

## 1. 执行摘要

微信与支付宝的第三方登录在 H5、微信小程序、App 三端的接入方式完全不同：**小程序端走宿主内置登录（wx.login → code2Session），App 端走开放平台移动应用 + 客户端 SDK 拉起授权，H5 端则严格依赖浏览器环境**——微信授权只能在微信内置浏览器内完成，支付宝授权在支付宝客户端内用 JSAPI、在客户端外用网页授权页（PC 扫码 / 唤起支付宝 App）。

uni-app 框架层只统一封装了「App 端微信登录」和「各家小程序内置登录」；**H5 端 uni.login 不提供任何三方登录能力（平台差异表标记为 x）**，App 端不内置支付宝登录，需要原生插件、UTS 插件或 web-view 方案自行集成[cite:21][cite:24]。

多端账号打通的关键是 **UnionID**：同一微信开放平台账号下的移动应用、网站应用、小程序、服务号，同一用户的 UnionID 一致，可作为统一的微信侧用户主键[cite:9]。支付宝侧则以 USER_ID（现 open_id 体系）作为用户主键，同一 app_id 下唯一[cite:18][cite:15]。

## 2. 能力矩阵总览

| 端 | 微信登录 | 支付宝登录 | uni-app 内置支持 |
|---|---|---|---|
| 微信小程序 | `uni.login` → code → 服务端 `auth.code2Session` 换 openid/unionid[cite:3][cite:4] | 不适用（宿主就是微信） | 完全内置[cite:21] |
| App（iOS/Android） | 开放平台「移动应用」+ 微信登录能力审核，manifest 勾选 OAuth，`uni.login({provider:'weixin'})` 拉起微信客户端授权[cite:1][cite:22] | 需接入支付宝客户端 SDK 拉起授权，uni-app 无内置封装，走原生插件/UTS 插件/web-view[cite:21][cite:14] | 微信有、支付宝无[cite:21] |
| H5（微信内置浏览器） | 服务号网页授权 OAuth2（snsapi_base / snsapi_userinfo）[cite:5] | 不适用 | 无内置，需自行实现[cite:21] |
| H5（普通浏览器 / PC） | 不可拉起微信授权；PC 端可用开放平台「网站应用」扫码登录[cite:6] | 网页授权 URL 跳转：PC 扫码确认，移动端唤起支付宝 App；支付宝客户端内用 JSAPI `ap.getAuthCode` 半屏授权[cite:13][cite:16][cite:17] | 无内置，需自行实现[cite:21] |

## 3. 微信登录接入

### 3.1 微信小程序端

小程序登录是三端中唯一完全闭环在微信体系内的方案，流程固定为三步[cite:3][cite:4]：

1. 小程序调用 `wx.login()`（uni-app 中为 `uni.login`）获取**临时登录凭证 code**，有效期短且只能使用一次；
2. 将 code 回传到开发者服务器，服务器调用 `auth.code2Session` 接口（`GET https://api.weixin.qq.com/sns/jscode2session`）换取 **openid、unionid（小程序已绑定微信开放平台账号时返回）、session_key**；
3. 服务器基于用户标识生成自定义登录态（自有 JWT），下发给小程序用于后续请求鉴权。

要点：

- `code2Session` **只能服务端调用**，AppSecret 不能出现在前端[cite:4]；
- 2021 年后 `wx.getUserProfile` / `uni.getUserInfo` 已被收回或返回匿名数据，微信官方改用「头像昵称填写能力」（基础库 2.21.2+，button open-type）获取头像昵称，**不再有弹窗授权获取昵称头像的方式**[cite:21]；
- 拿 unionid 的前提是把小程序绑定到一个**已完成开发者资质认证**的微信开放平台账号下[cite:9][cite:10]。

### 3.2 App 端

App 端微信登录基于微信开放平台的「移动应用」类目，OAuth2.0 授权登录体系[cite:1]：

1. 在微信开放平台注册开发者账号并完成**开发者资质认证**（非个人主体必须，需支付费用；微信体系内的认证收费为 300 元/次）[cite:10][cite:12][cite:26]；
2. 创建「移动应用」并提交审核（审核 1–7 个工作日，不需要提交 ipa 或先上架 App Store）[cite:26]，审核通过后在应用详情中**申请开通「微信登录」能力**并通过审核[cite:22]；
3. 获得 AppID / AppSecret 后接入客户端 SDK。

uni-app 具体接线方式[cite:22][cite:21]：

- manifest.json → App 模块配置 → OAuth(登录鉴权) 勾选「微信登录」，填写 AppID、iOS UniversalLinks（必须与开放平台后台配置一致，否则授权回跳失败或出现二次确认弹窗[cite:2]）；
- 调用 `uni.login({ provider: 'weixin' })` 拉起微信客户端授权；未安装微信时 5+ 内核会自动降级到 WAP 授权页[cite:24]；
- **强烈建议配置 `onlyAuthorize: true`**：默认模式下 SDK 会在客户端直接用 AppSecret 换取 authResult（打包后 AppSecret 存在于 apk/ipa 中，有泄露风险）；配置后只返回 code，由自有服务端完成 code → access_token/openid 的交换[cite:21]；
- HarmonyOS Next 端需额外按微信开放文档配置 queryScheme / actions（HBuilderX 4.81+）[cite:21]；
- 服务端拿 code 后调用 `https://api.weixin.qq.com/sns/oauth2/access_token` 换 openid/unionid（移动应用的 OAuth 交换与网站应用同源，返回字段含 unionid）[cite:1][cite:7]。

此外微信还提供了移动应用内**扫码登录**能力（`IDiffDevOAuth.startOAuth()` 在 App 内展示二维码，用户用微信扫码授权），支持 iOS/Android/鸿蒙，适合平板等没有微信客户端的场景[cite:11]。

### 3.3 H5 端

H5 端要区分两种运行环境，**这是三端中限制最大的一端**：

**① 微信内置浏览器内**：走服务号「网页授权」机制[cite:5]：

- 前提：拥有一个**已认证的服务号**（订阅号无网页授权能力，个人主体无法申请服务号）；
- 引导用户跳转 `https://open.weixin.qq.com/connect/oauth2/authorize?appid=...&redirect_uri=...&scope=snsapi_userinfo...`；
- scope 二选一：`snsapi_base`（静默授权，只拿 openid，用户无感）或 `snsapi_userinfo`（需用户点击同意，可拿昵称头像）；
- 回调拿到 code 后由服务端调用 `sns/oauth2/access_token` 换取网页授权 access_token 与 openid，`snsapi_userinfo` 下再调 `sns/userinfo` 拉取用户信息（服务端接口，有 5 万/分钟频控）[cite:8]。

**② 微信外的普通浏览器**：**无法拉起微信授权**（微信没有向外部浏览器开放登录 SDK）。PC 浏览器的替代方案是开放平台「网站应用」的扫码登录：跳转 `open.weixin.qq.com/connect/qrconnect` 展示二维码，用户微信扫码确认后回调 code，服务端同样走 `sns/oauth2/access_token` 交换[cite:6][cite:7]。移动端普通浏览器没有可用方案，一般回退到手机号验证码登录。

**uni-app H5 端注意**：`uni.login` 在 Web 平台标记为不支持[cite:21][cite:23]，微信内 H5 需要自行实现上述 OAuth 跳转流程（或引入微信 JS-SDK / jweixin 辅助库），DCloud 官方也明确该场景未封装在 uni.login 中[cite:21]。

### 3.4 UnionID：多端账号打通的核心

同一微信用户在不同公众号/小程序/移动应用下的 **openid 各不相同**；只要这些应用挂在**同一个微信开放平台账号**下，用户的 **unionid 全局唯一**[cite:9]。落地要点：

- 小程序：绑定到开放平台账号后，code2Session 直接返回 unionid[cite:3]；
- 移动应用 / 网站应用：OAuth 交换 access_token 后可直接返回 unionid（绑定开放平台的前提下）[cite:7]；
- 服务号网页授权：同上，需服务号绑定到同一开放平台账号[cite:9]；
- 后端账号体系建议以 unionid 为微信侧唯一键，各端的 openid 作为「端维度」的辅助字段存储。

约束：移动应用的主体需与同账号下绑定的小程序**同主体或关联主体**[cite:10]。

### 3.5 资质与成本小结（微信）

| 项 | 要求 |
|---|---|
| 微信小程序 | 个人主体可注册；但无认证则无法绑定开放平台、拿不到 unionid。企业认证 300 元/次[cite:12] |
| 微信开放平台账号 | 非个人主体必须完成开发者资质认证（付费）后才能创建/绑定移动应用、网站应用[cite:10][cite:26] |
| 服务号（H5 网页授权） | 仅企业主体可申请，需微信认证 300 元/次 |
| 移动应用微信登录能力 | 创建应用免费，需单独申请「微信登录」接口权限并过审[cite:22] |
| 审核周期 | 应用登记审核 1–7 个工作日[cite:26] |

## 4. 支付宝登录接入

### 4.1 通用授权模型

支付宝侧所有场景共用同一套「用户信息授权」模型，与微信类似但接口不同[cite:15][cite:18]：

1. 客户端/网页发起授权，获得 **auth_code**（一次性票据，24 小时未使用自动过期）；
2. 服务端调用 `alipay.system.oauth.token` 用 auth_code 换取 **access_token 与 user_id**；
3. 需要更多信息时，服务端用 access_token 调用 `alipay.user.info.share`（支付宝会员授权信息查询接口）获取昵称、头像、性别等。

scope 说明[cite:18]：

- `auth_base`：静默授权，不弹窗，只能换到 user_id；
- `auth_user`：主动授权，弹确认浮层，可换到详细信息（网站支付宝登录场景）。

### 4.2 App 端

App 端支付宝登录 =「App 支付宝登录」产品，流程为：客户端接入支付宝客户端 SDK → 拼接授权参数调用 SDK 唤起支付宝 App → 用户确认 → 回调 auth_code → 服务端 `alipay.system.oauth.token` 换 access_token → `alipay.user.info.share` 拿用户信息[cite:14][cite:15]。

- 未安装支付宝客户端时，SDK 会降级到 H5 授权页[cite:14]；
- **uni-app 没有内置支付宝登录**：uni.login 的 App 端支持列表只有 univerify/Apple/微信/QQ/微博/Google/Facebook/华为，不含支付宝[cite:21]。官方给出的集成路径有三条[cite:21]：
  1. 在 DCloud 插件市场找现成的「支付宝登录」原生插件（5+ App）；
  2. 用 UTS 插件自行封装支付宝 SDK；
  3. 内嵌 web-view 组件走网页授权模式。
- 服务端接入用支付宝官方 SDK（开放平台提供 Python/Java/PHP/.Net 等，FastAPI 项目可直接用 `alipay-sdk-python`），密钥模式推荐**公钥证书或公钥加签**，应用需配置「授权回调地址」与「接口加签方式」[cite:15][cite:25]。

### 4.3 H5 端

支付宝 H5 登录分三个环境[cite:13]：

**① 支付宝客户端内嵌 H5**：调用 JSAPI `ap.getAuthCode`（引入支付宝 JSAPI 脚本）在当前页面唤起**半屏授权浮层**，用户确认后回调 auth_code。注意 JSAPI 必须在**授权回调地址页面**中调用，否则无效[cite:17]。

**② 手机普通浏览器**：跳转网页授权链接 `https://openauth.alipay.com/oauth2/publicAppAuthorize.htm?app_id=...&scope=auth_user&redirect_uri=...`，页面会自动唤起支付宝 App 完成授权后回跳[cite:13][cite:16]。

**③ PC 浏览器**：同一个授权 URL，在 PC 上呈现为二维码，用户支付宝扫码确认后回跳 auth_code，与微信网站应用扫码登录形态一致[cite:16][cite:13]。

三种方式拿到的 auth_code 统一走 `alipay.system.oauth.token` + `alipay.user.info.share` 服务端交换，后端逻辑可以完全复用[cite:13]。

### 4.4 资质与权限要求（支付宝）

| 项 | 要求 |
|---|---|
| 入驻开放平台 | 个人/企业账号均可入驻，均需实名认证，无入驻费用[cite:25] |
| 创建应用 | 控制台创建网页/移动应用，配置授权回调地址、加签方式，应用上线审核[cite:25] |
| 「网站支付宝登录」「获取会员信息」权限 | 需在应用详情中申请开通（用户信息授权类产品）[cite:13][cite:18] |
| 基础 user_id | 个人开发者可获取（auth_base 静默授权也可）[cite:18] |
| 敏感字段（姓名、手机号等） | **仅企业账号可申请**，按行业审核；个人账号无申请入口[cite:19][cite:20] |
| 芝麻信用 scope（auth_zhima） | 另行开通，登录场景一般用不到[cite:18] |

## 5. 后端设计建议（自有 FastAPI 后端场景）

两端的服务端模型高度对称，建议抽象成统一结构：

```
POST /api/v1/auth/oauth/{provider}     # provider: weixin_app | weixin_mp | weixin_h5 | weixin_web | alipay
Body: { code, ... }
```

服务端流程：

1. **code 换身份**：按 provider 调用对应平台的交换接口（微信 `sns/oauth2/access_token` 或 `jscode2session`；支付宝 `alipay.system.oauth.token`），得到 `openid/user_id` + `unionid`；
2. **账号映射**：建一张 `oauth_bindings` 表（provider、openid、unionid/alipay_user_id、user_id 外键）。微信系各端优先用 unionid 归并到同一用户，无 unionid（如未绑开放平台）时按 openid 独立建户；支付宝用 user_id 建户；
3. **签发自有 JWT**：与现有手机号登录共用同一套用户表与令牌体系，OAuth 首次登录即自动注册，符合当前项目「登录成功后检查家庭/宝宝再强制引导」的既有逻辑；
4. **密钥管理**：微信 AppSecret、支付宝应用私钥全部放服务端环境变量（.env / .env.prod），绝不进前端与仓库。

## 6. 风险与注意事项

- **H5 端微信登录是硬伤**：普通移动浏览器无法微信授权，产品上必须保留手机号验证码作为兜底登录方式，微信授权只作为微信内环境的增强入口[cite:5][cite:6]；
- **微信小程序拿不到昵称头像**：`getUserProfile` 已收回，需改用「头像昵称填写能力」让用户主动填写[cite:21]；
- **AppSecret / 支付宝私钥安全**：App 端微信登录若不配 `onlyAuthorize:true`，AppSecret 会被打进安装包[cite:21]；支付宝私钥同样只能存服务端；
- **iOS Universal Links**：配置不一致会导致微信授权回不来或弹二次确认，需在开放平台后台与 Xcode 工程两侧严格一致[cite:2]；
- **审核周期**：微信移动应用审核 1–7 个工作日，微信登录能力另需单独审核；支付宝权限申请同样有审核期，建议资质申请先行、与开发并行[cite:26]；
- **企业主体依赖**：H5 微信网页授权（认证服务号）、支付宝敏感字段均为企业主体专属；个人主体只能做到小程序静默登录与支付宝 user_id 级登录[cite:19][cite:20]；
- **auth_code / code 一次性**：两端授权票据都只能用一次，需做好重试与防重放（换 token 失败时引导用户重新授权）[cite:4][cite:15]。

## 7. 结论与落地路线建议

1. **小程序端最先做、成本最低**：`uni.login` 原生支持，服务端加一个 code2Session 端点即可，且能直接拿 unionid；
2. **App 端微信登录第二**：走 uni-app 内置 OAuth 模块，资质认证（300 元）与能力审核周期长，尽早提交开放平台申请；代码层用 `onlyAuthorize:true` 模式；
3. **支付宝登录统一按「网页授权 + 客户端内 JSAPI」实现 H5 侧，App 侧评估插件市场现成原生插件**；若目标用户以家长/家庭场景为主、支付宝登录使用频率预期低，可先只做 H5 + 小程序形态，App 端支付宝登录后置；
4. **H5 端统一策略**：微信内浏览器走网页授权、支付宝内浏览器走 `ap.getAuthCode`、其他环境回退手机号验证码；三分支在前端入口层收敛，服务端按统一 `/auth/oauth/{provider}` 收口；
5. **账号体系以 unionid + alipay_user_id 做绑定表**，避免 openid 直接当用户主键，否则后续绑定开放平台/新增应用会导致同一用户裂变多个账号。

## 8. 个人开发者适配结论

若开发主体为**个人**（非企业/个体工商户），上述方案的可行性大幅收窄，逐项结论如下：

| 方案 | 个人主体可行性 | 原因 |
|---|---|---|
| 微信小程序登录 | ✅ 可行（仅 openid） | 个人主体可注册小程序，`code2Session` 正常可用 |
| 微信 UnionID 账号打通 | ❌ 不可行 | 个人小程序无法完成微信认证，无法绑定微信开放平台，拿不到 unionid[cite:10][cite:12] |
| App 端微信登录 | ❌ 不可行 | 微信开放平台开发者资质认证仅对非个人主体（企业/组织/个体工商户）开放，个人无法认证、无法创建并通过审核移动应用[cite:10][cite:26] |
| H5 端微信网页授权 | ❌ 不可行 | 服务号仅企业/组织主体可申请，个人无法获得网页授权能力[cite:5] |
| 支付宝 H5 登录 | ⚠️ 理论可行，需实测 | 个人实名账号可入驻开放平台并创建自用型「网页&移动应用」，用户信息授权准入「对支付宝企业账号和支付宝个人账号（含个体工商户）均开放」，`auth_base` 静默拿 user_id 应可用；但「网站支付宝登录」等权限的实际审核结果需在控制台申请验证，且敏感字段（昵称/头像/手机号）仅企业可申请[cite:18][cite:25] |
| 支付宝 App 登录 | ⚠️ 同上 + 集成成本高 | 权限同上；且 uni-app 无内置封装，需原生/UTS 插件 |

个人主体的现实可行路线：

1. **微信小程序端**：openid 静默登录作为唯一微信入口，接受「同一用户在 H5/App 无法与小程序账号打通」的现状（微信侧账号分裂）；
2. **App 端**：以**手机号验证码登录**（短信服务商个人认证可用）或 **DCloud 一键登录 univerify**（按次计费，个人开发者可用）为主登录方式；iOS 如不接入任何三方登录则无需强制 Apple 登录；
3. **H5 端**：手机号验证码登录为主，支付宝授权作为可选增强（先到支付宝控制台实际申请权限验证可行性）；
4. **低成本破局选项**：注册**个体工商户**（成本数百元内，部分地区线上可办）后，微信开放平台资质认证、服务号申请、支付宝敏感字段三条路全部解锁——如果产品后续要正经做多端账号统一，这是性价比最高的路径；
5. 账号表设计上仍建议预留 `oauth_bindings` 结构（provider + openid/user_id 列），未来主体升级为个体工商户/企业时迁移成本最低。

## 9. 补充调研：移动端与 H5 用短信登录的可行性

**结论：可行，且是个人开发者三端登录的最现实方案，但必须选对产品——普通短信服务已对个人关闭大门，应使用阿里云「短信认证服务」。**

### 9.1 关键政策变化（2025–2026 运营商实名报备收紧）

- 腾讯云短信：自 2025-09-18 起不再支持个人认证用户创建「自用签名/资质」，个人只能申请「他用签名」（即签名为其他企业名称并提供授权）；且运营商已不再支持「小程序/公众号/网站/APP」类型签名，推荐「公司」类型——个人用自己的产品名发短信这条路已被封死[cite:27][cite:28]。
- 阿里云短信服务：签名来源推荐企事业单位名；公众号/小程序/已备案网站来源「可能极大程度面临发送失败」；「已上线 APP」来源自 2026-04-27 起不再支持——个人无企业主体，普通短信服务的签名审核基本无法通过[cite:29]。
- 价格：国内验证码短信约 0.043–0.05 元/条（腾讯云 1 万条 470 元≈0.047/条；阿里云短信服务 0.047 起、短信认证服务 0.045 起，促销活动更低）[cite:30][cite:31]。

### 9.2 个人开发者正解：阿里云「短信认证服务」（PNVS 子服务）

- **免资质**：无需营业执照、无需申请签名和短信模板，个人实名认证账号即可开通并直接调 API；
- 平台**系统赠送签名和标准验证码模板**（唯一可用选项，不支持自定义），验证码可由平台自动生成或自定义，核验也由平台 API 完成（SendSmsVerifyCode / CheckSmsVerifyCode）；
- 支持 **App、Web、H5、小程序**全平台调用，与本项目三端场景完全匹配；
- 发送失败不计费；套餐折合 0.045 元/条起（促销活动曾低至 3.99 元/年），个人项目月成本通常几元以内[cite:32][cite:33]；
- 取舍：短信内容为平台标准格式（含平台签名），无法展示自有品牌名——个人主体下这是当前唯一合规低成本通道。

### 9.3 接入与安全要点

- 后端新增 `POST /auth/sms/send`（服务端调阿里云 API 发码）与 `POST /auth/sms/login`（CheckSmsVerifyCode 核验通过后签发自有 JWT），以手机号作为账号唯一键，与现有密码登录账号体系合并；
- 防刷（短信是登录接口中最易被刷的）：发送前加图形/滑块验证码、同手机号 1 条/分钟 + 5 条/天、同 IP 限流、验证码 5 分钟有效、错误次数锁定；
- 合规：登录页需勾选《用户协议与隐私政策》后再发码，验证码短信正文不得含营销内容；
- H5 本身用 IP:端口访问（当前 49.233.77.155:30080 形态）不涉及 ICP 备案；若后续绑定国内域名对外提供 Web 服务，域名需完成 ICP 备案（个人也可备案，但流程约 2–4 周）。
